# Delivery velocity: causes, evidence and intervention choices

September 30, 2026. This analysis corrects the first plan pack's emphasis on finishing individual V44 routes. The objective is to make future features cheaper to develop, qualify and accept. V44 failures are evidence for that objective, not the implementation backlog for this pack.

Source baseline: published `a3fcc9e4184006ee22abe850d01c1f84f80b34bb`; earlier V44 private-candidate evidence remains explicitly attributed to `1d683cf8`/e11. Read-only source/selector analysis and existing results were used. No application tests, matcher/OCR replay, emulator work or new performance benchmark ran. Policy changes at a3 are already published; the earlier pack's pending-policy notes are historical.

## What the first pass missed

It identified fixture fallback, incomplete handoffs and shared capacity, but treated the existing architecture, discovery tooling and acceptance workflow mostly as fixed constraints. It also prescribed more checklists before checking whether the same facts were already represented in several places. The deeper questions are: why does one feature select so many tests; why does every new UI boundary require custom capture preparation; why must a correction cross so many ownership boundaries; and why is acceptance reconstructed from prose?

## Norms to retain, operational overreach to remove, changes to pilot

Retain exact target/role/lease ownership, fresh frame and action provenance, no replay after uncertain mutation, and final proof of material live behavior. They protect real correctness and cannot be replaced by a green process exit.

Apply existing norms as written: a complete broad gate is not required before every discovery capture; unchanged accepted routes do not need repeated tours; castle identity can be reused while continuity holds; unrelated recoverable popups need not terminate independent cases; successful normal popup handling is not a new failure incident. Audit actual assignments for stricter inherited requirements before rewriting skills.

Pilot changes where existing tooling is insufficient: source-editing development assignments with explicit frozen live phases, one supported discovery capture boundary, structured results instead of repeated prose, and dependency-scoped acceptance. Final independent acceptance remains separate. A broader queue exception remains a user sequencing decision; this planning request does not silently revoke V44-first.

## Priority and falsification

The later [coordinator review and sequence](../V44_QUALITY_REVIEW_AND_SEQUENCE.md) supersedes the initial priority recommendation below: the demonstrated shared-publication mapping divergence is Q1, fixture ownership Q2, complete neutral contracts Q3, and combined case/result/discovery tooling Q4. Larger navigation extraction and test deletions require additional evidence. The causal analysis remains evidence; it is not an independent release order.

1. Start with 09's ownership pilot and 15's live-tooling/gate separation: strongest concrete symptoms and bounded changes.
2. Run 14's contract-import pilot alongside light preparation; broaden modularization only if consumer maps/change ownership improve without hiding consumers.
3. Use 11 to eliminate mechanical handback repair. Keep 13's few timestamps to check whether review/queue delay then dominates.
4. Apply 10's WIP/release discipline now; propose a V44 queue exception only for a named ready consumer with demonstrated blocked value.

Stop or change direction if a proposed split leaves the same imports/selection, a test consolidation loses a unique assertion, a new helper recreates runtime policy, or a reporting change increases duplicate maintained state. Do not promise percentage speedups without comparable observations. This pack intentionally avoids a repo-wide rewrite, a new scheduler, blanket removal of live tests, or adding agents as the default remedy.
